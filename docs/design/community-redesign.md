# 设计 Prompt · 社区二创分区重构（作者分栏 + 类型分流）

> 本文是**实现前的设计契约**。先定稿，再动代码；实现完按 §7 验收。
> 状态：待实现 · 基线 commit `a2543a4`

---

## 1. 问题（用数据说话，不用感觉）

`docs/community/_meta.json` 147 件作品 / 41 位作者，实测分布：

| 观察 | 数据 | 含义 |
| --- | --- | --- |
| 形状高度同质 | 近方 48 + 竖图 48 = **96/147** 是单角色图 | 一面"证物墙"，观感重复 |
| 作者极不均衡 | 1 位 16 张、1 位 12、1 位 10、1 位 9 … **25 位只有 1 张** | 直接"一人一栏"会碎成 25 个小节 |
| 「作者未知」是个陷阱 | **36 张**（占 24%），其中 33 张是梗图 | 它**不是一位画师**，是一组历史梗图；当作"第一大栏"反而更乱 |
| 真正的同质块 | **89 张角色立绘**，分属 16 位画师 | 这才是要拆解的对象 |

## 2. 设计决策

### 2.1 双轴，而不是单轴

```
主轴：内容类型   →  直接回答"角色内容太多"
副轴：作者       →  用户要的"依据作者分栏"
```

单靠作者分栏解决不了问题：89 张立绘里有 25 位作者各 1 张，一人一栏后仍然是"89 张立绘"，
只是被 25 个标题切碎了。**必须先按类型分流，把角色立绘单独拎出来，再在类型内部按作者成栏。**

### 2.2 分类器（可复现，写进 `_meta.json`）

按 `id 形态 → 标题关键词 → 宽高比` 依次判定，产出 `type` 字段：

| type | 判定规则 | 预期件数 |
| --- | --- | --- |
| `meme` 表情包 | `id` 以 `meme-` 开头，或标题含「表情包 / 梗图」 | 40 |
| `sheet` 设定图 | 标题含「三视图 / 设定图 / character sheet」 | 12 |
| `scene` 场景壁纸 | 标题含「壁纸 / 背景 / 场景」，或宽高比 > 1.5 且宽 ≥ 1200 | 6 |
| `character` 角色立绘 | 其余全部 | 89 |

判定不了的一律归 `character` 并在灯箱里标「未分类」，**不猜**。

### 2.3 作者分栏的三条规则

1. **≥2 件的作者 → 独立"系列栏"**：栏头 = 作者色竖线 + 作者名 + 件数 + 投稿链接，栏内是自己的作品网格。
2. **仅 1 件的作者 → 不单独成栏**，并入该类型末尾的「其他创作者」**署名卡墙**（小方卡：缩略图 + 作者名）。
   理由：25 个只含一张图的栏 = 25 个视觉碎片，信息密度反而更低。
3. **「作者未知」不是作者**，作为独立栏目「上游未标注作者 · N 件」放在其作品所属的类型下，
   栏头显式写明"上游未标注作者"，**不与真实作者混排**（合规：署名缺失要如实显示，不能伪装成一位画师）。

### 2.4 作者强调色

`hue = md5(作者名) → 0..359`，`sat=62% light=66%`。用于栏头竖线、署名卡边框、卡片角标。
**同一作者永远同色**（哈希稳定，重建不漂移）。

## 3. 信息架构

```

├── 视图切换     [ 按作者分栏 ] [ 全部平铺 ]

│
└── 「按作者分栏」视图
    ├── 角色立绘 · 89 件
    │   ├── ▌紫纹缃核 · 16 件 ──────────── [图][图][图][图][图][图]…
    │   ├── ▌AATINF · 12 件 ────────────── [图][图]…
    │   ├── ▌JerryZRic · 9 件 ──────────── [图][图]…
    │   ├── …（≥2 件的作者共 16 位，按件数降序）
    │   └── 其他创作者（各 1 件）· 25 ───── [小卡][小卡][小卡]…（署名卡墙）
    ├── 表情包 · 40 件
    │   ├── ▌标准大气吖 · 2 件 …
    │   └── ▌上游未标注作者 · 36 件 …

```

「全部平铺」视图 = 现有瀑布流（类型筛选照常生效）。

## 4. 卡片减噪（web design 的核心）

现状：每张卡 3 行文字（标题 / 创作类型 / 作者）+ 2 个链接，147 张 = 文字墙。

改后：

| 元素 | 处理 |
| --- | --- |
| 标题 | **保留一行**（作品名，13px）—— 作品名是识别信息 |
| 创作类型那一行 | **删掉**，改成标题前的一个类型色点（点击可按类型筛选） |
| 作者 | **保留一行**（11.5px，作者色）—— **合规要求：署名必须在作品旁边** |
| 链接行（原图 / 投稿 #N） | **从卡片移除**，移入灯箱（灯箱已有「原图 / 高清版 / 投稿出处」三个链接） |
| hover | 图片轻微缩放 + 底部渐变浮出标题；作者色边框高亮 |
| 无 JS | 整卡仍是 `<a>`，直接打开原图 → 降级不丢功能 |

## 5. 视觉规范

| 项 | 值 |
| --- | --- |
| 作者强调色 | `hsl(md5(author)%360 62% 66%)` |
| 类型色点 | 角色 `#5fc8ff` / 表情包 `#ff8a6b` / 设定图 `#f0c987` / 场景 `#5fe0b0` |
| 栏头 | 2px 作者色竖线 + 15px 作者名 + 12px 件数（muted） |
| 栏间距 | 类型之间 44px，栏与栏之间 30px，栏内 18px（章节感） |
| 卡片 | 圆角 12、边框 1px `--line`、背景改为平的表面色（去掉渐变，网格里太吵） |
| 卡片 hover | `transform: translateY(-2px)` + 边框转作者色 + 标题浮层淡入 |
| 署名卡（小卡） | 缩略图 + 下方作者名 11px，网格 `minmax(96px,1fr)` |
| 动效 | 全部 `prefers-reduced-motion` 友好（沿用现有全局降级） |

## 6. 实现约束

1. **分类与作者分栏都要生成，不手写** —— 新增 `tools/build_cards.py` 的输出层：
   `_meta.json` 增加 `type` 字段；卡片 HTML 增加 `data-type` / `data-author`。
2. **瀑布流要支持多个 grid** —— 现在每个 `.grid` 独立算行高；作者视图下会有 41 个 grid。
   **必须改成"先读完所有 caption 高度，再统一写 span"**，否则 41 轮读写交错 = 布局抖动，卡。
3. **筛选要联动重排** —— 隐藏卡片时跳过它参与行高计算（`layoutGrid` 里 `continue`），并 `layoutAll(true)` 重算。
4. **无 JS 降级** —— 两个视图都是静态 HTML，JS 只做切换；禁 JS 时只显示「全部平铺」+ 全部类型（筛选器隐藏）。
5. **不改图片、不改许可、不改署名** —— 这轮只重排信息与视觉。
6. **页头统计**升级为「147 件 · 41 位创作者」，并新增类型分布说明。
